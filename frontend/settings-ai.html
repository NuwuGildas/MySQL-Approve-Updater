Server access (SSH) only for the server you attach from Servers → Terminal

The assistant works on one attached server at a time. Every command is classified before it runs: read, write or destructive. Anything interactive (editors, top, nested ssh) is always refused, and every command is written to History.

Lets it look around by itself: ls, cat, df, systemctl status, journalctl, docker ps, git log… These run immediately and change nothing.

Editing files, restarting services, installing packages, git pull. Each command appears in the chat as a card showing exactly what would run; nothing happens until you press Run it.

Deleting, formatting, rebooting, dropping databases, git reset --hard. These are never run automatically, even in auto mode.

Without this, any command using sudo is refused whatever its class.

Write commands you allowed above run without asking each time, so the assistant can finish a task in one go. Destructive commands still stop for approval. Read-only commands never needed it.

What you discussed and which commands ran are kept per server in ssh-agent-memory.json, and given back as context the next time you connect. The assistant can search it (ssh_recall) and add notes (ssh_remember).

Without this, the coding agent on a server uses its own login there, and you renew it by running claude in that server's terminal when it expires. With it, each run borrows this application's AI token instead — handed over on stdin, so it is never in a command line and never written to that machine, and it is gone when the run ends. It is still readable by that server's user and by root while it runs, so leave this off for a server whose root you do not trust. It needs a token this application holds: connect the assistant with Claude (API key or sign-in token) — claude setup-token makes one for exactly this, separate from your main login and revocable on its own.
